# Контрольная M06 — recon

> Время: 🟢 60 мин · 🟡 3 ч · 🔴 5–6 ч. Сдаётся в `labs/m06-recon/exam/`.

## 🟢 Задача 1. Пассивный профиль (60 мин)

**Дано:** публичный домен `example.com` (только пассивные источники) и ваша лаборатория.

**Задание:**
1. Соберите NS, MX, TXT, поддомены из CT-логов.
2. Найдите 3 исторических URL из архива.
3. Для лаборатории составьте список хостов без сканирования (ARP/DHCP/known).
4. Оформите таблицу «актив — источник — уверенность».

**Сдать:** `passive.md`, `sources.txt`.

**Критерии:** источники (30), полнота (30), структура (20), дата/уверенность (20).

---

## 🟡 Задача 2. Активный recon лаборатории (3 ч)

**Дано:** `10.10.10.0/24`.

**Задание:**
1. Найдите все хосты и открытые порты.
2. Определите версии сервисов и web-технологии.
3. Найдите минимум 3 скрытых пути и 1 vhost (создайте его сами, если нет).
4. Для каждого сервиса предложите 1–2 гипотезы атаки.
5. Зафиксируйте, какие логи это оставит.

**Сдать:** `active/` — nmap-отчёты, ffuf-результаты, `findings.md`.

**Критерии:** хосты/порты (30), версии (20), скрытые пути (20), гипотезы (20), OPSEC (10).

---

## 🔴 Задача 3. Recon-пайплайн (5–6 ч)

**Дано:** лаборатория, Python/Bash.

**Задание:**
1. Напишите пайплайн: вход — CIDR/домен, выход — JSON + Markdown.
2. Этапы: host discovery → port scan → service detection → web paths (для 80/443/8000) → сохранение.
3. Обязательно: scope guard (запрет всего вне `10.10.10.0/24`), rate limit, логирование, таймауты.
4. Запустите на лаборатории, приложите результат.
5. README с этикой и ограничениями.

**Сдать:** `recon/` — код, тесты (mock), `README.md`, `output/`.

**Критерии:** работает (30), scope guard и безопасность (25), качество кода (20), отчёт (15), README (10).
