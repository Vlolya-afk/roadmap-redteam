# 6.1 — Пассивный recon

> **M06 · Этап 1 · 3 ч · 🟢 · артефакт:** `labs/m06-recon/l01-passive/`

## Цель

Собрать максимум информации о домене, не отправляя ни одного пакета на его инфраструктуру.

## Результат

- Список поддоменов, DNS-записей, технологий и исторических данных.
- Понимание, какие источники что дают и где врут.
- `passive/report.md` с источниками и выводами.

## Теория

- Пассивный recon не касается цели: whois, DNS, CT-логи, архивы, поисковики.
- Certificate Transparency (crt.sh) — публичный лог сертификатов; часто выдаёт внутренние имена.
- DNS: NS/MX/TXT/SPF/DMARC раскрывают почтовую инфраструктуру и подрядчиков.
- Wayback Machine показывает старые версии, забытые страницы, параметры.
- Shodan/Censys — уже просканированный интернет; запрос к ним не является сканом цели.
- Данные устаревают: фиксируйте дату и источник.

## Лаборатория

### 1. Who is

```bash
whois example.com | sed -n '1,40p'
dig +short NS example.com
dig +short MX example.com
dig +short TXT example.com
```

Ожидаемо: регистратор, NS-серверы, почтовые серверы, TXT (SPF, verification). Запишите, кто хостит DNS.

### 2. Certificate Transparency

```bash
curl -s "https://crt.sh/?q=%25.example.com&output=json" \
  | jq -r '.[].name_value' | tr ',' '\n' | sort -u | head -30
```

Ожидаемо: список имён из сертификатов. Обратите внимание на `*.example.com` и внутренние имена.

### 3. Архив

```bash
curl -s "http://web.archive.org/cdx/search/cdx?url=example.com/*&output=json&collapse=urlkey&limit=50" \
  | jq -r '.[1:][] | .[2]' | head -30
```

Ожидаемо: исторические URL. Ищите `admin`, `api`, `backup`, параметры `id=`.

### 4. Инструменты

```bash
# пассивный amass (без активных запросов)
amass enum -passive -d example.com -o passive/amass.txt

# theHarvester
theHarvester -d example.com -b duckduckgo,bing -f passive/harvester.html
```

Ожидаемо: файлы с поддоменами и упоминаниями. Сравните источники: расхождения — норма.

### 5. Отчёт

Заполните таблицу:

| Актив | Источник | Дата | Уверенность |
|---|---|---|---|
| www.example.com | crt.sh | 2026-11-02 | высокая |
| dev.example.com | архив | ... | средняя |

## Атака и защита

- **Атака:** CT-логи выдают staging/dev, которые забыли закрыть; старые страницы — входы без MFA.
- **Детект:** пассивный recon не детектится (вы не касаетесь цели), но запросы к API crt.sh видны вашему провайдеру.
- **Фикс:** не выпускать сертификаты на внутренние имена, закрывать staging, чистить архив (сложно), инвентаризация.
