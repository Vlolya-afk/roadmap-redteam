# 6.2 — OSINT по людям и организациям

> **M06 · Этап 1 · 3 ч · 🟡 · артефакт:** `labs/m06-recon/l02-osint/`

## Цель

Научиться собирать контекст об организации и сотрудниках легально: почтовые форматы, роли, публичные утечки, метаданные.

## Результат

- Профиль вымышленной компании: сотрудники, роли, почтовый формат.
- Понимание, как проверять собственный цифровой след.
- Этическая рамка: что можно и что нельзя.

## Теория

- OSINT — работа с публичными данными, а не «пробив». Разница — в источнике и целях.
- Почтовый формат (`first.last@`, `flast@`) выводится из публичных профилей и подтверждается SMTP-проверкой (только в своей лабе).
- Утечки (HIBP, DeHashed) показывают, какие пароли сотрудники использовали; использовать их для входа нельзя.
- Метаданные документов (`exiftool`) выдают имена, ПО, пути, иногда GPS.
- GitHub — источник секретов: `.env`, ключи, внутренние URL.
- Социальная инженерия по реальным людям без разрешения — вне закона и вне этики.

## Лаборатория

### 1. Свой след

```bash
# Проверьте свою почту на публичные утечки (веб-интерфейс)
# https://haveibeenpwned.com/

# Метаданные своего фото/файла
exiftool ~/Pictures/photo.jpg | head -30
```

Ожидаемо: список утечек (или «нет») и метаданные (камера, ПО, дата). Удалите GPS-теги из публичных фото.

### 2. GitHub-поиск

Веб-поиск (без API-ключей):

```
org:YOUR_ORG password
org:YOUR_ORG filename:.env
"lab.local" password
```

Локально по своему репозиторию:

```bash
grep -rInE '(password|secret|token|api[_-]?key)\s*[=:]' . --exclude-dir=.git
```

Ожидаемо: если находите — это ваша находка в собственном проекте. Исправьте и ротируйте.

### 3. Профиль вымышленной компании

Создайте `osint/company.md` для вымышленной «Northwind Labs»:

| Поле | Значение | Источник |
|---|---|---|
| Домен | northwind.example | whois |
| Почтовый формат | first.last@ | сайт, вакансии |
| Ключевые роли | CTO, DevOps, Finance | LinkedIn (вымышленные профили) |
| Технологии | nginx, Windows, M365 | вакансии, Shodan (только свои) |
| Публичные утечки | нет | HIBP |

Цель — научиться структурировать, а не «копать» реальных людей.

### 4. Email-формат (в лабе)

Поднимите SMTP-заглушку и проверьте гипотезу формата:

```bash
python3 -m smtpd -n -c DebuggingServer 127.0.0.1:2525
# в другом терминале
printf 'EHLO lab\r\nMAIL FROM:<a@lab>\r\nRCPT TO:<alice@lab.local>\r\nQUIT\r\n' | nc 127.0.0.1 2525
```

Ожидаемо: диалог SMTP. В реальной проверке формат подтверждают по ответу `RCPT TO` (250/550), но только в рамках разрешённого теста.

## Атака и защита

- **Атака:** фишинг под конкретного сотрудника (spearphishing), подбор пароля из утечки, доступ по утёкшему токену.
- **Детект:** аномальные входы, MFA-отказы, новые устройства, письма с внешнего домена.
- **Фикс:** MFA, менеджер паролей, обучение, запрет публикации внутренних деталей, мониторинг утечек.
