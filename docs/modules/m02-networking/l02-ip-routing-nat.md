# 2.2 — IP, подсети, маршрутизация, NAT

> **M02 · Этап 0 · 4 ч · 🟢 · артефакт:** `labs/m02-networking/l02-ip-routing/`

## Цель

Считать подсети без калькулятора и понимать, куда уйдёт пакет. Это нужно для любого сканирования и для планирования лаборатории.

## Результат

- Считаете сеть/broadcast/диапазон для маски от `/24` до `/30`.
- Читаете `ip route` и `ip route get`.
- Объясняете NAT и почему цель в лаборатории не должна иметь NAT-адаптер.

## Теория

- IPv4 = 32 бита, маска отделяет сеть от хоста. `/24` = 256 адресов, 254 хоста.
- Приватные диапазоны: `10/8`, `172.16/12`, `192.168/16`.
- Маршрутизация: longest prefix match. `0.0.0.0/0` — default route.
- `ip route get <ip>` показывает, какой маршрут и source будет выбран.
- NAT/PAT меняет src IP/port на выходе; обратная трансляция — по таблице состояний.
- TTL уменьшается на каждом hop; `traceroute` использует это.
- ICMP redirect может подменить маршрут — редко, но опасно.

## Лаборатория

### 1. Разминка по подсетям

Для каждого префикса определите network, broadcast, первый/последний хост, количество хостов:

| CIDR | Network | Broadcast | Hosts |
|---|---|---|---|
| 10.10.10.50/26 | | | |
| 192.168.56.10/28 | | | |
| 172.16.5.130/25 | | | |
| 10.0.0.7/30 | | | |

Проверка:

```bash
ipcalc 10.10.10.50/26
```

(На Arch: `pacman -S ipcalc`.)

### 2. Маршруты

```bash
ip route
ip route get 10.10.10.30
ip route get 8.8.8.8
```

Ожидаемо: для цели — `dev <vmnet2> src 10.10.10.50`, для интернета — через NAT-интерфейс.

### 3. Добавить и удалить маршрут

```bash
sudo ip route add 10.99.0.0/24 via 10.10.10.30
ip route get 10.99.0.5
sudo ip route del 10.99.0.0/24
```

Ожидаемо: пакет пойдёт через LNX01. Если LNX01 не умеет forward — дальше не уйдёт. Это модель pivot.

### 4. Blackhole и диагностика

```bash
sudo ip route add blackhole 10.66.0.0/24
ping -c 1 10.66.0.1        # сразу "unreachable"
sudo ip route del blackhole 10.66.0.0/24
traceroute -n 8.8.8.8
```

Ожидаемо: blackhole даёт мгновенный `Network is unreachable`, а не таймаут. Разница важна при диагностике.

### 5. NAT глазами пакета

На attacker:

```bash
sudo tcpdump -n -i any icmp
ping -c 2 8.8.8.8
```

Ожидаемо: source — `192.168.150.x` (NAT-адрес), не `10.10.10.50`. Если видите `10.10.10.50` в интернете — у вас неправильная схема, разберитесь.

## Атака и защита

- **Атака:** подмена default gateway, ICMP redirect, маршрут в «ловушку» для перехвата.
- **Детект:** изменения таблицы маршрутизации, ICMP redirect от не-шлюза, аномальный TTL.
- **Фикс:** статические маршруты на критичных узлах, `accept_redirects=0`, сегментация, контроль конфигурации.
