# 13.5 — OPSEC C2 и burn-план

> **M13 · Этап 2 · 6 ч · 🔴 · артефакт:** `labs/m13-initial-access-c2/l05-c2-opsec/`

## Цель

Научиться планировать операцию так, чтобы её можно было безопасно завершить: минимизировать IOC, логировать действия, иметь план на случай обнаружения.

## Результат

- OPSEC-чеклист инфраструктуры.
- Burn-план с триггерами и действиями.
- Таблица «артефакт → где остаётся → как убрать».

## Теория

### 1. Принципы

- **Минимум артефактов** на хосте: память лучше диска, но не всегда.
- **Разделение** инфраструктуры по операциям и целям.
- **Одноразовость** доменов и IP.
- **Логирование** собственных действий (для отчёта и дебриф).
- **Согласование** с клиентом: что можно, что нельзя, когда стоп.

### 2. IOC

Indicators of Compromise: хэши, домены, IP, URI, mutex, named pipes, сертификаты, User-Agent. Чем меньше уникальных IOC, тем сложнее защитнику связать события. Но «не оставлять IOC» не должно превращаться в «скрывать от клиента» — отчётность важнее.

### 3. Гигиена

| Область | Правило |
|---|---|
| Инфраструктура | отдельный VPS/аккаунт на операцию, без личных данных |
| Домены | регистрация с приватностью, разные регистраторы |
| TLS | Let's Encrypt или валидный CA, без самоподписи в проде |
| C2 | jitter, sleep, профиль под легенду |
| Хосты | минимум файлов, очистка после |
| Креды | не хранить в открытом виде, не переиспользовать вне операции |
| Коммуникация | только согласованные каналы |

### 4. Burn-план

Триггеры:

- защитник заблокировал домен/IP;
- EDR начал алертить на implant;
- клиент просит остановиться;
- обнаружена утечка данных за пределы согласованного.

Действия:

1. Остановить активность.
2. Сохранить логи и доказательства.
3. Уведомить клиента по протоколу.
4. Удалить инфраструктуру (или передать клиенту).
5. Разобрать в дебрифе.

### 5. Юридическая рамка

RoE определяет: какие системы, какие техники, окна, контакты, запреты. Всё, что вне RoE — стоп. Это не формальность: за неё сажают.

## Лаборатория

> Любая лабораторная инфраструктура из 13.1–13.4. Цель — не новая атака, а план.

### 1. Инвентаризация

Составьте список всех компонентов: домены, IP, сертификаты, implants, аккаунты. Для каждого — владелец и срок жизни.

### 2. IOC-лист

| Артефакт | Где | Уникальность | Можно ли уменьшить |
|---|---|---|---|

### 3. Логи

Включите логирование:

```bash
# nginx
access_log /var/log/nginx/access.log;
# sliver
# в консоли: jobs, sessions, loot
```

Ожидаемо: вы можете восстановить таймлайн.

### 4. Триггеры

Опишите 4 триггера и действия. Проверьте на сценарии «домен заблокирован».

### 5. Уборка

```text
sessions
kill <id>
```

Остановите listener, удалите implant, отзовите сертификат (в лабе — удалить), снесите ВМ.

### 6. Отчёт

Напишите `burn-plan.md` на 1–2 страницы: компоненты, триггеры, действия, контакты, сроки.

## Атака и защита

- **Атака:** минимизировать и разделять.
- **Детект:** threat intel, корреляция, egress.
- **Фикс:** egress-контроль, IR-план, контакты с клиентом, tabletop-учения.
