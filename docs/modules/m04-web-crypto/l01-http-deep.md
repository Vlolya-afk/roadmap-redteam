# 4.1 — HTTP глубже

> **M04 · Этап 0 · 4 ч · 🟢 · артефакт:** `labs/m04-web-crypto/l01-http/`

## Цель

Читать HTTP так, как его читает сервер, и понимать, какие заголовки меняют поведение безопасности.

## Результат

- Разбираете запрос/ответ по частям.
- Управляете cookies, редиректами и методами через `curl`.
- Объясняете CORS, CSP, HSTS и `SameSite`.

## Теория

- Запрос: метод, путь, версия, заголовки, тело. Ответ: версия, статус, заголовки, тело.
- Методы: GET (идемпотентный), POST, PUT, PATCH, DELETE, HEAD, OPTIONS.
- Статусы: 200, 201, 204, 301/302, 304, 400, 401, 403, 404, 405, 429, 500, 502, 503.
- `Set-Cookie` → `Cookie`; флаги `HttpOnly`, `Secure`, `SameSite`.
- `Origin` + CORS-заголовки решают, может ли JS с одного сайта читать ответ другого.
- CSP ограничивает источники скриптов; HSTS заставляет браузер использовать HTTPS.
- HTTP/2 мультиплексирует потоки; HTTP/3 на QUIC/UDP.

## Лаборатория

### 1. Запрос и ответ

```bash
curl -v http://10.10.10.30:8000/ 2>&1 | sed -n '1,40p'
curl -s -D - -o /dev/null http://10.10.10.30:8000/
```

Ожидаемо: request line, `Host`, `User-Agent`, `Accept`, затем статус и заголовки ответа.

### 2. Методы

```bash
curl -i -X OPTIONS http://10.10.10.30:8000/
curl -I http://10.10.10.30:8000/
curl -i -X POST -d 'a=1' http://10.10.10.30:8000/
```

Ожидаемо: `OPTIONS` может вернуть `501`/`200`, `HEAD` — только заголовки, `POST` — `501` у простого `http.server`. Зафиксируйте, какие методы разрешены.

### 3. Cookies и редиректы

```bash
curl -c /tmp/cookies.txt -b /tmp/cookies.txt -L -v http://10.10.10.30:8000/ 2>&1 | grep -i 'set-cookie\|location'
```

Ожидаемо: если сервер ставит cookie — увидите `Set-Cookie`; `-L` идёт по `Location`.

### 4. Заголовки безопасности

```bash
curl -s -D - -o /dev/null https://example.com | grep -iE 'strict-transport|content-security|x-frame|referrer'
```

Ожидаемо: список заголовков (или их отсутствие). Объясните, чего не хватает и чем это грозит.

### 5. Burp

Поставьте Burp (Community) или Caido, настройте proxy `127.0.0.1:8080`, импортируйте CA-сертификат в браузер, откройте DVWA. В **Proxy → HTTP history** найдите запрос логина и отправьте в **Repeater**. Измените параметр, посмотрите ответ.

## Атака и защита

- **Атака:** HTTP request smuggling (несогласованность `Content-Length`/`Transfer-Encoding`), cache poisoning, header injection, cookie theft.
- **Детект:** аномальные заголовки, расхождение длины, подозрительные `User-Agent`, всплеск 4xx.
- **Фикс:** нормализация на прокси, строгий парсинг, CSP/HSTS, `SameSite=Lax/Strict`, запрет лишних методов.
