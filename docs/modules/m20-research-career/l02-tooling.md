# 20.2 — Свой инструмент

> **M20 · Этап 3 · 5 ч · 🟡 · артефакт:** `labs/m20-research-career/l02-tool/`

## Цель

Написать небольшой, но качественный инструмент: CLI, тесты, документация, упаковка, CI. Не «скрипт на коленке», а проект.

## Результат

- Репозиторий с инструментом.
- Тесты и README.
- CI, который проходит.

## Теория

### 1. Выбор задачи

- Автоматизация повторяющегося действия.
- Парсер логов/конфигов.
- Обёртка над API.
- Проверка конфигурации (security check).

Не начинайте с «нового C2». Начните с полезного малого.

### 2. Язык

- Python — быстро, богатые библиотеки.
- Go — бинарник, concurrency.
- Rust — безопасность, производительность.
- Bash — только glue.

### 3. Структура

```text
tool/
  cmd/ или tool/
  tests/
  README.md
  pyproject.toml / go.mod
  .github/workflows/ci.yml
```

### 4. Качество

- Типы, линтер (`ruff`, `go vet`).
- Тесты (pytest, go test).
- Обработка ошибок.
- Логи, а не `print`.
- `--help`, exit codes.

### 5. Безопасность

- Не логировать секреты.
- Валидировать вход.
- Не выполнять shell без нужды.
- Ограничивать ресурсы.

### 6. Документация

README: что, зачем, установка, примеры, ограничения, лицензия. Без этого инструментом не пользуются.

## Лаборатория

> Ваш репозиторий.

### 1. Идея

Выберите задачу из своей практики (например, парсер Sigma или проверка Sysmon-конфига).

### 2. Скелет

```bash
mkdir mytool && cd mytool
python3 -m venv .venv
# pyproject.toml, src/, tests/
```

### 3. Код

Реализуйте MVP: 1 команда, 1 функция, 10–30 строк логики.

### 4. Тесты

```bash
pytest -q
```

Ожидаемо: 3+ теста, покрытие основной логики.

### 5. CI

```yaml
name: ci
on: [push]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with: {python-version: '3.12'}
      - run: pip install -e .[dev]
      - run: ruff check .
      - run: pytest -q
```

### 6. README

Напишите так, чтобы человек без контекста запустил за 2 минуты.
