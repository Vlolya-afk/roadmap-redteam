# Топология VMware и бюджет ресурсов

## Установка VMware Workstation на Arch

```bash
# Зависимости
sudo pacman -S --needed linux-headers gtkmm3 libcanberra

# Пакет из AUR (Workstation Pro бесплатен для личного использования)
paru -S vmware-workstation

# Сервисы
sudo systemctl enable --now vmware-networks.service
sudo systemctl enable --now vmware-usbarbitrator.service
```

Проверка модулей ядра:

```bash
lsmod | grep -E 'vmmon|vmnet'
sudo vmware-networks --status
```

Если после обновления ядра модули не собираются — переустановите AUR-пакет (`paru -S vmware-workstation`) или используйте `vmware-host-modules`.

> На официальном сайте Broadcom нужен аккаунт для скачивания. AUR-пакет собирает то же самое. Для личного использования лицензия бесплатна; для коммерческого — покупайте.

## Виртуальные сети

Откройте **Virtual Network Editor** (`sudo vmware-netcfg`).

| Сеть | Тип | Подсеть | DHCP | Назначение |
|---|---|---|---|---|
| VMnet0 | bridged | — | — | **Не использовать** |
| VMnet1 | host-only | 192.168.56.0/24 | **выключить** | Управление и атака |
| VMnet2 | host-only | 10.10.10.0/24 | **выключить** | «Корпоративная» сеть |
| VMnet8 | NAT | 192.168.150.0/24 | включить | Интернет для обновлений |

**Почему DHCP выключен:** статические IP делают лабы воспроизводимыми. DHCP-аренда меняется после снапшота и ломает конфиги.

### IP-план

| Хост | IP | Сеть | Роль |
|---|---|---|---|
| `attacker` (Arch) | 192.168.56.10 | VMnet1 | Основная атакующая ВМ |
| `attacker` (2-й NIC) | 10.10.10.50 | VMnet2 | Доступ в «корпоративную» сеть |
| `kali` (опц.) | 192.168.56.11 | VMnet1 | Альтернативный инструментарий |
| `DC01` | 10.10.10.10 | VMnet2 | Windows Server, домен `lab.local` |
| `WS01` | 10.10.10.20 | VMnet2 | Windows 11, рабочая станция |

| `docker-host` | 10.10.10.40 | VMnet2 | DVWA/Juice Shop в контейнерах |

Шлюз для VMnet2 не нужен: сеть изолирована. Если цели должны обновляться — временно добавьте им второй адаптер в VMnet8, обновите, выключите.

## Установка Windows-целей

ISO берите только официально:

- Windows Server 2022/2025 Evaluation — Microsoft Evaluation Center (180 дней).
- Windows 11 Enterprise Evaluation — там же (90 дней).

Порядок:

1. Создайте ВМ: 2 vCPU, 3–4 ГБ RAM, 50–60 ГБ, UEFI, **один** адаптер VMnet8 (NAT) на время установки.
2. Установите Windows, поставьте обновления, установите VMware Tools (меню VM → Install VMware Tools, затем `windows.iso` в приводе).
3. Настройте статический IP и переключите адаптер на VMnet2.
4. **Сразу сделайте снапшот** `clean-install`. Активация/триал идут от первого запуска — снапшот фиксирует состояние.
5. Отключите сон, автообновление и восстановление — они ломают лабы.

### Статический IP в Windows

```powershell
New-NetIPAddress -InterfaceAlias "Ethernet0" -IPAddress 10.10.10.10 -PrefixLength 24
Set-DnsClientServerAddress -InterfaceAlias "Ethernet0" -ServerAddresses 10.10.10.10
```

Для WS01 — `10.10.10.20`, DNS `10.10.10.10`. Для DC01 DNS указывает на себя.

### Linux-цель (Ubuntu Server)

```bash
# /etc/netplan/01-lab.yaml
network:
  version: 2
  ethernets:
    ens33:
      dhcp4: false
      addresses: [10.10.10.30/24]
      routes:
        - to: default
          via: 10.10.10.1   # только если есть шлюз; в изолированной сети не нужен
```

```bash
sudo netplan apply
```

## Снапшоты: политика

| Имя | Когда | Что фиксирует |
|---|---|---|
| `clean-install` | сразу после установки и настройки IP | Чистая система |
| `pre-attack` | перед каждой лабой | Рабочее состояние |
| `post-attack` | после лабы, **если** хотите сохранить следы | Компрометация |
| `golden` | после настройки домена (M05) | Эталон для клонирования |

Правила:

- Перед атакой — **всегда** `pre-attack`. Откат — 30 секунд, пересборка домена — 2 часа.
- Снапшот с памятью ест диск. Для лаб достаточно снапшота без памяти (ВМ выключена).
- Имя = дата + причина: `2026-11-02-pre-kerberoast`.
- После отката проверьте время и сеть: `timedatectl`, `ip a`.

## Клонирование

- **Full clone** — независимая копия, занимает место.
- **Linked clone** — быстро и экономно, но зависит от родителя. Удалите родителя — умрут клоны.
- Для домена клонируйте **до** `sysprep`/ввода в домен, иначе получите дубликаты SID и конфликт имён. Для учебного AD проще пересобрать.

## Синхронизация времени

После снапшота часы часто уезжают, а Kerberos не любит расхождение > 5 минут.

Linux-гость:

```bash
sudo vmware-toolbox-cmd timesync enable
sudo systemctl restart systemd-timesyncd
```

Windows-гость:

```powershell
w32tm /resync /force
# На DC:
w32tm /config /manualpeerlist:"time.windows.com" /syncfromflags:manual /reliable:yes /update
Restart-Service w32time
```

## Диагностика

| Проблема | Решение |
|---|---|
| ВМ не видит сеть VMnet2 | Проверьте, что адаптер подключён к Custom: VMnet2, а не Bridged |
| Два хоста не пингуются | Отключите firewall на время лабы или разрешите ICMP |
| Нет интернета в ВМ | Адаптер VMnet8 + NAT-сервис `vmware-networks` |
| Медленно | Выключите 3D-ускорение, уменьшите RAM, закройте браузер на хосте |
| `vmmon` не грузится | `linux-headers` + переустановка AUR-пакета |
| Кракозябры в консоли Linux | `setfont ter-v32n`, локаль UTF-8 |

## Чек-лист стенда

- [ ] VMnet1 и VMnet2 созданы, DHCP выключен
- [ ] Bridged-адаптеров нет ни у одной ВМ
- [ ] attacker имеет 2 NIC: VMnet1 и VMnet2
- [ ] DC01 пингуется с attacker по 10.10.10.10
- [ ] LNX01 пингуется по 10.10.10.30
- [ ] Снапшоты `clean-install` есть у всех ВМ
- [ ] Время на всех ВМ совпадает (±1 мин)
- [ ] `free -h` на хосте показывает ≥ 3 ГБ свободных при трёх ВМ
