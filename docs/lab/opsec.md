# OPSEC и изоляция лаборатории

OPSEC в обучении — это не про «скрыться от ФБР», а про то, чтобы **не навредить себе и другим**: не вынести стенд в интернет, не слить креды, не попасть в чужую сеть.

## Семь правил

1. **Host-only по умолчанию.** Bridged-адаптер — только осознанно и на 5 минут (обновления), потом выключить.
2. **Свой scope.** IP только из `10.10.10.0/24` и `192.168.56.0/24`. Если видите чужой — стоп.
3. **Снапшот до атаки.** Всегда. Откат — часть гигиены, а не признак неудачи.
4. **Никаких реальных данных.** Имена, пароли, почты — вымышленные. Домен — `lab.local`.
5. **Секреты — вне git.** Токены C2, API-ключи, приватные ключи, `.env`, дампы — в `.gitignore`.
6. **Публикация после санитайза.** Хэши, IP, имена хостов, скриншоты — проверить перед коммитом.
7. **Стоп-кран.** Вы понимаете, как остановить лабу (снапшот, `docker down`, выключить ВМ) до того, как начали.

## Изоляция по слоям

| Слой | Что делаем |
|---|---|
| Гипервизор | VMnet1/VMnet2 host-only, DHCP off, bridged отключён |
| Хост | nftables: input drop, forward — только vmnet8; отдельный пользователь для лаб |
| ВМ | Статические IP, без общего доступа к папкам хоста (кроме read-only) |
| Контейнеры | Отдельная docker-сеть, без `--privileged` (кроме лаб escape, осознанно) |
| Аккаунты | Отдельная почта для cloud/OSINT, MFA, никаких личных аккаунтов |
| Данные | Шифрованный контейнер (LUKS/VeraCrypt) для дампов, срок хранения |

## OSINT и «цифровой след»

Если вы изучаете OSINT на реальных людях/компаниях — только пассивно и только публичные данные. Не создавайте фейковые аккаунты для социальной инженерии без письменного разрешения: это уже активное воздействие.

Для лаб используйте **свои** тестовые профили и вымышленные компании.

## Облако без сюрпризов

- Отдельный аккаунт, отдельная карта с лимитом, budget alerts на $1–5.
- MFA включён, root-аккаунт не используется.
- Все ресурсы — в Terraform, чтобы `destroy` убивал всё.
- Теги `owner=lab`, `ttl=2d`, автоудаление.
- Проверка биллинга раз в день. Забытый NAT Gateway или EKS — это десятки долларов в сутки.
- Для дешёвых лаб: LocalStack (AWS), Azurite (Azure), kind (K8s) — бесплатно и без интернета.

## RF и hardware

- Передавайте **только** в экранированном боксе или на фиктивную нагрузку (dummy load). Антенна в эфире — это уже передача.
- Wi-Fi-атаки — только на своей точке доступа, в помещении, где нет чужих сетей, или на изолированном канале.
- Не глушите чужие сигналы: deauth — это радиочастотное вмешательство, в многих странах регулируется.
- RFID-клонирование — только своих меток.

## Санитайз перед публикацией

Чек-лист для каждого writeup:

- [ ] Нет реальных IP/доменов (только `lab.local`, RFC1918)
- [ ] Нет хэшей, паролей, токенов, ключей (даже «учебных» — соблазн)
- [ ] Нет персональных данных
- [ ] Скриншоты не содержат имени хоста работодателя, почты, вкладок с личным
- [ ] Дампы и pcap — не в git
- [ ] Нет инструкций «как атаковать чужой сервис»
- [ ] Есть дисклеймер «только для собственной лаборатории»

## Инцидент в лаборатории

Если что-то пошло не так:

1. **Остановите** ВМ/контейнер.
2. **Зафиксируйте** время и действие (это пригодится для разбора).
3. **Откатите** снапшот.
4. **Проверьте**, не ушёл ли трафик наружу: `tcpdump -i any -n 'not net 10.10.10.0/24 and not net 192.168.56.0/24'`.
5. **Запишите** урок в `journal/incidents.md` — без самобичевания, с конкретным фиксом.
