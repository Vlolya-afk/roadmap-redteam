# Как учиться по этому треку

## Режим

- **Минимум 10–12 часов в неделю**, разбитых на 3–4 блока по 2–3 часа. Один длинный блок в выходные + короткие вечером будни.
- **Один урок = один блок.** Не растягивайте урок на неделю: теряется контекст, лаба разваливается.
- **Правило 70/30.** Прочитали теорию — сразу руками. Если после урока у вас нет запущенной лабы и артефакта, урок не закрыт.
- **Неделя buffer.** Раз в 4 недели — пустая неделя на добивание хвостов и повторение. Без неё трек умирает на третьем месяце.

## Ритуал урока

1. **5 минут — план.** Прочитали заголовок, «Цель» и «Результат». Сформулировали, что должно получиться.
2. **20–30 минут — теория.** Только минимум из урока + 1–2 ссылки. Не уходите в rabbit hole.
3. **60–90 минут — лаба.** Делаете, ломаете, чините. Каждую нетривиальную команду — в заметку.
4. **20 минут — разбор.** Ответили на самопроверку, записали «почему это работает» своими словами.
5. **15 минут — артефакт и коммит.** Writeup + скриншоты + скрипт → `labs/`.

## Как вести заметки

Держите три уровня:

| Уровень | Где | Зачем |
|---|---|---|
| Быстрые заметки | `journal/YYYY-MM-DD.md` (в `.gitignore`, если личное) | Мысли по ходу, ошибки, тайминги |
| Writeup лабы | `labs/mXX-name/writeup.md` | Публичный артефакт, проверяемый |
| Конспект темы | `docs/modules/mXX-*/lNN-*.md` (дополняйте) | Ваша база знаний, из которой потом собираются ответы на интервью |

Пишите **своими словами**. Если не можете объяснить без подглядывания — вы не поняли.

## Шаблон writeup

```markdown
# M05 · L03 — Kerberoasting в lab.local

## Цель
Получить TGS для сервисной учётки и восстановить пароль офлайн.

## Стенд
- DC01 10.10.10.10 (Windows Server 2022, lab.local)
- WS01 10.10.10.20 (Windows 11)
- Attacker 10.10.10.50 (Arch, impacket 0.12)

## Ход
1. ...
2. ...

## Результат
- Хэш: `$krb5tgs$23$*svc_sql$...` (обрезан)
- Пароль восстановлен за 4 мин на RTX 3060 / 40 мин на CPU

## Почему сработало
SPN привязан к учётке, TGS шифруется ключом из её пароля, запрос может сделать любой
аутентифицированный пользователь, а Kerberos не ограничивает частоту.

## Защита
- gMSA для сервисов, 25+ символов, ротация
- Honey-account со SPN + алерт на 4769 с RC4
- Мониторинг аномального объёма 4769

## Что осталось непонятным
...
```

## Git-дисциплина

- Ветки не нужны, если вы учитесь один: работайте в `main`, но коммитьте осмысленно.
- Формат коммита: `feat(m05): add kerberoasting lab writeup`.
- Один урок — один коммит (или два: лаба + writeup).
- Крупные бинарники (ISO, pcap, дампы) — не в git. Ссылка + хэш в writeup, файл в Releases или локально.
- Перед коммитом: `python scripts/check-links.py`.

## Как проверять себя

**Лестница понимания:**

1. Могу повторить команды по шпаргалке. → *уровень копирования, не зачёт.*
2. Могу сделать лабу без шпаргалки, объясняя каждый шаг. → *зачёт урока.*
3. Могу объяснить, как это детектить и как защитить. → *уровень middle.*
4. Могу адаптировать технику под другую среду и написать свой инструмент/детект. → *уровень senior-track.*

После каждого модуля — контрольная. Зелёная задача обязательна, жёлтая — для зачёта модуля, красная — для портфолио и резюме.

## Что делать, когда застряли

1. **15-минутное правило**: 15 минут сами, потом идёте в документацию инструмента, потом в поиск.
2. **Читайте логи и ошибки целиком**, а не первую строку.
3. **Сужайте**: ping → порт → сервис → версия → эксплойт. Не прыгайте сразу в Metasploit.
4. **Ведите «журнал тупиков»**: что пробовали, что не сработало. Через месяц это ваша самая ценная база.
5. **Спросите**: сформулируйте вопрос так, чтобы в нём уже была половина ответа. Если не получается — вы ещё не разобрались.

## Как читать на GitHub

Сайт не нужен: GitHub рендерит Markdown сам. Навигация:

1. Начните с [основного README](README.md) — там маршрут и правила трека.
2. Откройте [карту этапов](roadmap.md) и [чек-лист прогресса](progress.md).
3. Модули лежат в `docs/modules/mXX-*/`: `index.md` (цель и критерии), уроки `lNN-*.md`, `exam.md`.
4. Свои writeup и артефакты складывайте в `labs/` — они тоже будут видны в репозитории.

Локальный просмотр не обязателен: обычный редактор с предпросмотром Markdown показывает всё то же самое. Если форкаете репозиторий, GitHub автоматически отрендерит и ваш форк.

Не публикуйте: реальные IP/домены работодателя, чужие персональные данные, дампы паролей, лицензионные ISO. Всё в writeup — из вашей лаборатории.
